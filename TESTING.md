# Проверка Handily 0.5.1

Среда: Java 21, Minecraft 1.21.1, NeoForge 21.1.265, Farm & Charm 1.1.29, Diegesis 1.0.0-beta.8, Architectury 13.0.11, вложенный Foundation 1.0.7. Дополнительно: Candlelight 2.1.15, Bakery 2.1.11, Hands-On Delight 1.4.0, Farmer's Delight 1.3.4.

## Сервер

```text
gradlew.bat runGameTestServer -PgameTests -Pcompat --offline
gradlew.bat runGameTestServer -PgameTests --offline
```

Оба запуска: **18 из 18 GameTest прошли**. Второй запуск идёт только с обязательными модами; проверки Candlelight и Bakery в нём пропускаются.

Покрытые сценарии 0.5.1:

- Порция по нажатию посудой на результат: расходуется ровно одна ёмкость, выход станции уменьшается на одну порцию, освободившийся курсор получает блюдо.
- Заполненный инвентарь и посуда на курсоре: при отсутствии места не расходуется ни посуда, ни еда.
- Shift-выдача: используются ёмкости из инвентаря и запас станции; в инвентаре остаются только неиспользованные ёмкости.
- ПКМ посудой в руке снаружи сцены: одна порция, последняя ёмкость заменяется блюдом.
- Жидкость публикуется уже при изменении слота, без первого перемешивания.
- Доска: нарезка тесаком и ножом с родным порогом, износом и побочными продуктами; сборка всех доступных рецептов; атомарный перенос; очередь из 16 предметов; воткнутый нож; заполненный выход; торт с возвратом трёх вёдер.
- Кастрюля: готовка ровно за 700 тиков без перемешивания, около 467 с перемешиванием, без нагрева прогресса нет, выдача требует настоящую ёмкость.
- Candlelight: большой котёл использует штатный инвентарь, крышка убрана, жидкость есть до первого движения ложки; сковородка не получает свойств крышки жаровни; печи Candlelight сохраняют свой интерфейс.
- Bakery: штатный рецепт, требование помешивания, разлив в банку и расход одной банки.
- Ориентация: доска и мясорубка выровнены по блоку; печь сохраняет фиксированный передний ракурс.

`KitchenGameTests.java` содержит исторические проверки версии 0.1.0 и исключён по умолчанию. Его старые результаты не подтверждают поведение текущей версии.

## Клиент

```text
gradlew.bat runClient -PvisualTests -PcompatVisual -Pcompat --offline
```

Отдельный тестовый мир `run-client/saves/Showcase`. Сценарий берёт предмет через API инвентаря, открывает доску с севера, кладёт еду настоящим кликом по сцене и проверяет, что три предмета остались в блоке, а курсор опустел. Затем открываются сковородка Candlelight, большой котёл (пустое дно), жаровня, варенье Bakery и кастрюля Farm & Charm; проверяется жидкость без перемешивания и вид станций в обычном мире. В конце доска открывается с восточной стороны: камера оказывается в `(2.3125, 72.21875, 0.5)`, то есть сразу восточнее блока, без промежуточного перелёта к передней стороне. Отдельный шаг открывает мясорубку и подтверждает, что её штатная модель видна.

Снимки `run-client/screenshots/handily-051-*.png`:

- `board` и `board-east` — доска с севера и с востока, книга и результат повёрнуты к камере, рабочая поверхность остаётся на месте;
- `pan`, `roaster-plating`, `roaster-world` — сковородка и жаровня;
- `candlelight-empty-floor`, `candlelight-world-floor` — открытый котёл без крышки, видимое дно и ложка;
- `soup-without-stirring-world` — жидкость в мире до перемешивания;
- `bakery-jam` — варенье;
- `mincer-world` — штатная модель мясорубки в сцене.

Клиентский запуск завершился с `BUILD SUCCESSFUL`; все проверки `HANDILY_CHECK ... PASS` присутствуют в `handily-051-client2.log`.

## Границы проверки

Автоматические проверки и снимки не заменяют длительную игру с двумя сетевыми клиентами, всеми модами пользовательской сборки и шейдерами. Одновременная выдача двумя игроками проверена логикой на серверной стороне (единый серверный поток, атомарное планирование), но не отдельным сетевым прогоном. Полный перебор бонусов костюма повара не выполнялся. Задержка открытия доски измерена косвенно: каталог, инструменты и геометрия больше не пересобираются при каждом открытии; отдельного профилировщика в тестовой среде нет. Папка основной пользовательской сборки не изменялась.
